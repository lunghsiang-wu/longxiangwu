1 Data description and import

The data set used in this case is credit card customer data. The specific data includes: the number of each customer case, the customer’s credit card limit, gender, education level, marital status, age, monthly repayment status during the data recording period (April-September 2005), billing records and payment records, in order to And the record of whether the customer breached the contract in the next month. The table information of the specific data field is recorded as follows:

Column name Meaning description Data type
ID Customer ID. int64
LIMIT_BAL The credit limit given by the bank to customers, including the personal credit limit and the customer’s family credit limit. float 64
Sex The gender of the client. Males are written as 1 and females are 2. int64
Education The customer’s education level. Graduate students and above are recorded as 1, universities are recorded as 2, high school students are recorded as 3, and others are recorded as 0. int64
MARRIAGE The client’s marital status. Unmarried is recorded as 2, married is recorded as 1, and others are recorded as 0. int64
Age The age of the customer. int64
PAY_1～PAY_6 These six variables are the monthly repayment records from April to September 2005, with values of -1 to 9, representing the cumulative number of overdue months. int64
BILL_AMT1～BILL_AMT6 These six variables are the monthly billing records from April to September 2005, that is, the monthly credit card consumption records. float 64
PAY_AMT1～PAY_AMT6 These six variables are the monthly payment records from April to September 2005, including the amount of bill repayment and the amount deposited on the credit card. float 64
default.payment.next.month On behalf of whether the customer will breach the contract next month, the breach of contract shall be recorded as 1, and if there is no breach of contract, it shall be recorded as 0. int64

2.2Data cleaning

First, use value_counts to check the field of education level:

df['EDUCATION'].value_counts()

THE VALUES OF EDUCATION LEVEL EDUCATION MARKED WITH 4, 5 AND 6 CAN BE UNDERSTOOD AS “OTHER”, WHICH REPRESENTS LOWER THAN HIGH SCHOOL EDUCATION. In order to sort the education from low to high, it is also necessary to swap the data tags labelled 1 and 3. We use replace to complete the above replacement, and the inplace parameter is set to True to replace the original data.

df['EDUCATION'].replace([1,3,4,5,6],[3,1,0,0,0],inplace=True)
df['EDUCATION'].value_counts()

In the data of gender SEX, men and women are marked as 1 and 2, and it is more in line with programming habits if we replace them with 0 and 1.

df['SEX'].replace([1,2],[0,1],inplace=True)
df['SEX'].value_counts()

We also check the marital status MARRIage column as well.

df['MARRIAGE'].value_counts()

Martal status marked as 3 can be understood as “other”, and we change it to the corresponding value of “other” to 0.

df['MARRIAGE'].replace(3,0,inplace=True)
df['MARRIAGE'].value_counts()

Finally, we also check the columns PAY_1 to PAY_6 that mark the repayment status. First of all, take the column PAY_1 as an example.

df['PAY_1'].value_counts()

The repayment of -2, -1 and 0 shall be regarded as debt repayment, and we will uniformly mark it as 0. After verification, the data from PAY_1 to PAY_6 has the same characteristics. We use iloc to locate the column we want to replace and carry out the replacement operation.

df.iloc[:,[6,7,8,9,10,11]] = df.iloc[:,[6,7,8,9,10,11]].replace([-2,-1],[0,0])
df.iloc[:,[6,7,8,9,10,11]].describe()

Sample labels should only be predicted as 0 and 1. We are more interested in the ratio of different labels and use the Series returned by value_counts to calculate.

df['default.payment.next.month'].value_counts()[0]/df['default.payment.next.month'].value_counts()[1]

It can be seen that the labelling ratio of the two samples is about 3.5, and there is a problem of class imbalance in the data.

3 Classification modelling

First of all, we try to use some basic machine learning models to directly classify and model the data, and give the prediction results of the classification. We choose the more classic KNN and decision tree to observe the effect.

3.1 KNN model

In the KNN model, because it involves the concept of distance in Euclidean space, for unordered discrete variables, dumb variable coding should be done first. WE ENCODE THE DISORDERED DISCRETE VARIABLES SEX AND MARRIAGE WITH DUMB VARIABLES.

str_columns = ['SEX','MARRIAGE']

df_new

We divide the data set into label column y and feature column X to prepare for later processing.

y = df_new['default.payment.next.month']
X = df_new.drop(columns=['ID','default.payment.next.month'])

For numerical variables, the range of numerical changes defined by different variables is very different, and we should also standardise this part of the data. Since the maximum and minimum value of some variables in the population is unknown (such as the customer’s credit card limit LIMIT_BAL), we choose ZScore to standardise the characteristic column to standardise the processing, so that each column of data after processing is a data with an average value of 0 and a standard deviation of 1.

X = X.astype(float)
X.iloc[:, 0:20] = preprocessing.scale(X.iloc[:, 0:20])
X.sample(5)

In order to show the effect of the classification model, we need to obtain the AUC score (accuracy_score), classification report and confusion matrix of the model. In order to facilitate subsequent use, we define a function Get_report to obtain this information.

def Get_report(testers , predictors):
    print ('The AUC Score of the model is：{a}'.format(a=metrics.accuracy_score(testers, predictors)))
    print ('The classification report of the model is shown as follows:')
    print (metrics.classification_report(testers, predictors))
    print ('The confusion matrix of the model is shown as follows:')
    plt.figure(figsize=(8,4))
    ConfMatrix = confusion_matrix(testers, predictors)
    sns.heatmap(ConfMatrix,annot=True, cmap="Blues", fmt="d", 
            xticklabels = ['No breach of contract', 'Breach of contract'], 
            yticklabels = ['No breach of contract', 'Breach of contract'])
    plt.ylabel('Real label')
    plt.xlabel('Predictive label')
    plt.title("Confusing matrix")

We pass the y_test and knn_pred obtained before to this function to show the classification effect report of the KNN model.

Get_report(y_test , knn_pred)

We found that although the accuracy of the overall forecast is not bad, the actual recall rate of the default sample is only 0.27, and the f1-score that can comprehensively show the accuracy and recall rate of positive samples is only 0.36. Let’s try other models for comparison.

5 XGBoost

Next, we introduce a powerful algorithm - XGBoost, which is one of the representatives of Boosting. It is an improvement on GBDT (Gradient Boosting Decision Tree). We learn after resampling the data.

from xgboost import XGBClassifier
model = XGBClassifier(
    booster='gbtree',
    learning_rate=0.1,
    gamma=1,
    scale_pos_weight=1,
    n_estimators=1000,
    max_depth=6,
    alpha=5,
    reg_lambda=1,
    early_stopping_rounds=10,
    eval_metric="auc"  # moved here too
)

eval_set = [(X_test, y_test)]
model.fit(X_train, y_train, eval_set=eval_set, verbose=False)
y_pred = model.predict(X_test)
y_socre = model.predict_proba(X_test)[:,1]
predictions = [round(value) for value in y_pred]
Get_report(y_test,y_pred)

The learning_rate parameter represents the learning rate, which determines whether the target function can converge to the local minimum value and when it converges to the minimum value. alpha and reg_lambda correspond to L1 and L2 regular term coefficients respectively.

6 Conclusion

The final classification effect obtained in this case is not satisfactory. The best AUC value is about 0.8, and the highest F1 value obtained from the positive sample is 0.55. For scenarios such as credit card default, which requires high recall rate of positive samples, higher recall rate and accuracy are often required. However, due to data limitations, it is difficult for this data set to achieve a good classification effect on the final results, but the processing and reference of different algorithms and indicators are worth reviewing.
